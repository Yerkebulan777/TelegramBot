# Полная очистка TelegramBot при деинсталляции

## Цель

Деинсталлятор удаляет установленные компоненты, стандартные внешние файлы TelegramBot и рабочие данные PostgreSQL. При этом он сохраняет Telegram-пользователей, не изменяет роли PostgreSQL и не касается пользовательских или сетевых каталогов, заданных конфигурацией.

## Принятые решения

### Telegram-пользователи

Вернуть только самостоятельный справочник `BotUsers`, без удалённой ранее системы заявок, статусов доступа и Telegram-ролей. Таблица содержит `UserId`, последнее известное `Username`, `CreatedAt` и `UpdatedAt`. Server выполняет идемпотентный upsert пользователя после проверки rate limit и непустого имени, до обработки сообщения или callback.

При инициализации схемы существующие уникальные пользователи однократно переносятся из `Sessions`; это сохраняет пользователей уже работающей установки. История сессий не становится хранилищем пользователей.

### Очистка PostgreSQL

Установщик использует единый CLI-helper жизненного цикла вместо отдельных одноразовых программ и разрастающейся Pascal-логики. Helper читает ту же цепочку конфигурации, что Server и Worker, и предоставляет отдельные явные команды для проверки подключения и деинсталляционной очистки.

После остановки Server и Worker helper выполняет одной транзакцией `TRUNCATE ... RESTART IDENTITY` для следующих таблиц:

- `NotificationOutbox`;
- `TrackedMessages`;
- `Commands`;
- `Sessions`;
- `RuntimeSettings`;
- `RevitLaunchState`.

Таблица `BotUsers`, схема базы, сама база и кластерные роли PostgreSQL не изменяются. Таблицы перечисляются явно; `CASCADE`, динамическое перечисление схемы и удаление базы запрещены, чтобы новые или чужие таблицы не попадали под очистку автоматически.

Если PostgreSQL недоступен, helper возвращает ошибку, деинсталлятор показывает предупреждение и продолжает удаление файлов. Потеря соединения не должна оставлять частично очищенную базу благодаря транзакции.

### Стандартный внешний каталог

Удаляется только каталог, который приложение само определило как стандартный `Environment.SpecialFolder.MyDocuments/TelegramBot`. Произвольные значения `FileSystem:LogDirectory` и `FileSystem:TaskDirectory`, UNC-пути и другие сетевые каталоги не записываются как цели удаления.

Во время установки lifecycle-helper преобразует выбранную учётную запись в SID, определяет её системный каталог Documents и записывает вычисленный путь в `HKLM\Software\TelegramBot`. Раздел создаёт elevated-установщик, поэтому runtime-учётная запись Server/Worker не может подменить цель будущего удаления. Сначала helper читает `User Shell Folders\Personal` из загруженного пользовательского hive; если профиль ещё не загружен, использует `ProfileList\<SID>\ProfileImagePath\Documents`.

При деинсталляции helper читает сохранённое значение из HKLM, нормализует путь через `Path.GetFullPath`, запрещает корень диска и reparse points, сверяет путь с тем же SID профиля и проверяет конечное имя `TelegramBot`, затем рекурсивно удаляет каталог и значение реестра. Некорректная или отсутствующая запись вызывает предупреждение без удаления. Это исключает использование `{userdocs}`, которое может указывать на профиль администратора, а не учётной записи Server/Worker, и не доверяет файлам из доступной службе папки `{app}`.

### Порядок деинсталляции

1. Остановить службу Server и задачу Worker.
2. Выбрать существующую конфигурацию Server, иначе Worker.
3. Очистить рабочие таблицы PostgreSQL, сохранив `BotUsers`.
4. Удалить подтверждённый стандартный каталог `Documents/TelegramBot` и lifecycle-значение HKLM.
5. Удалить регистрацию службы и задачи планировщика.
6. Удалить весь каталог установки `{app}`.

Повторный запуск каждого шага безопасен: отсутствующие таблицы, каталог, служба или задача не считаются ошибкой.

## Рассмотренные альтернативы

### Восстановить прежнюю систему авторизации

Отклонено: она была намеренно удалена коммитом `fa10f0b`, а текущей задаче нужен только устойчивый справочник пользователей. Возврат заявок, ролей и middleware существенно расширил бы поведение продукта.

### Сохранить пользователей внутри `Sessions`

Отклонено: это не позволяет одновременно очистить историю и сохранить пользователей, а также смешивает две разные сущности.

### Удалять `{userdocs}/TelegramBot` напрямую из Inno Setup

Отклонено: деинсталлятор может выполняться под другим администратором и удалить не тот каталог. Маркер фактического стандартного пути сохраняет корректную привязку к профилю процесса.

## Проверка

Репозиторий запрещает добавлять тесты, поэтому проверка состоит из полной сборки `dotnet build TelegramBot.slnx`, сборки Inno Setup через `Installer.build.proj` и статической проверки сценариев helper: сохранение `BotUsers`, явный список очищаемых таблиц, отказ от удаления произвольного пути и идемпотентный повторный запуск.

Документация поведения деинсталлятора обновляется в `README.md`, а состав и порядок очистки PostgreSQL — в `Docs/ExecutionAlgorithm.md`.
