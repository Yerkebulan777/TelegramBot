# Inline-действия выбора файлов: дизайн

## Цель

Убрать reply-клавиатуру из потока выбора проекта и RVT-файлов. Все действия
пользователь выполняет inline-кнопками в одном сообщении выбора.

## Пользовательский поток

1. При выборе команд их список содержит inline-кнопки `✅ Применить` и
   `❌ Отмена`; reply-клавиатура не создаётся.
2. После применения выбранных команд бот показывает список проектов с
   inline-кнопками. Reply-клавиатура не создаётся.
3. Нажатие на кнопку проекта сразу открывает `<проект>/01_PROJECT` и показывает
   список разделов.
4. На уровне `01_PROJECT` кнопка `⬅️ Назад` возвращает к списку проектов.
5. В разделе пользователь выбирает файлы, открывает вложенные уровни и при
   необходимости возвращается назад существующей inline-навигацией.
6. На уровнях выбора файлов клавиатура содержит отдельный ряд:
   `✅ Подтвердить` и `❌ Отмена`.
7. `✅ Подтвердить` использует существующую семантику подтверждения: без файлов
   показывает ошибку, с файлами создаёт заявки в очередь.
8. `❌ Отмена` сбрасывает поток выбора, удаляет отслеживаемые сообщения и не
   создаёт заявок.

## Архитектура

- `KeyboardBuilder` строит только inline-разметку для действий выбора файлов;
  методы построения reply-клавиатуры и отправки reply-сообщений удаляются.
- `FileSystemBrowser` добавляет ряд действий к файловому представлению, а
  проектный и разделовый уровни остаются навигационными. Переход из проекта
  выполняется текущим `SelectionFlow.OpenFolder`, который сразу добавляет
  `01_PROJECT`.
- `FileSelectionHandler` обрабатывает новые callback-префиксы подтверждения и
  отмены вместе с toggle, select-all и навигацией. Подтверждение переиспользует
  существующую логику формирования заявок; отмена переиспользует сброс и очистку
  текущего представления.
- Сервис жизненного цикла reply-клавиатуры удаляется из DI и потребителей.

## Ошибки и ограничения

- Callback-аргументы и пути продолжают валидироваться внутри корневого каталога.
- Поведение при пустом выборе файлов не меняется: заявка не создаётся.
- Все обновления происходят в текущем inline-сообщении; отдельное постоянное
  сообщение «Действия» не отправляется.

## Проверка

- Полная сборка `dotnet build TelegramBot.slnx`.
- Ручная проверка: список проектов → проект → `01_PROJECT` → «Назад»;
  выбор/снятие файлов; «Выбрать все»; подтверждение с файлами и без; отмена.
